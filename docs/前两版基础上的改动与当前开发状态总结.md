## 一、总体结论

当前版本以原始 `Tsing-RADAR` 为主线，没有直接覆盖合并 `tsing-radar-patched`，而是选择性吸收 patch 中正确的协议方向，再重新实现其未完成或存在安全问题的部分。

项目处于「站内闭环可在本地真实运行的候选版本」阶段：

- 清小搭兼容的 OpenAI 风格 API 已实现并通过本地合同测试；
- GLM/DeepSeek 的外部模型调用适配器已编写，但**当前环境未配置密钥，主链路未真实调用外部大模型**；
- v2.2 在原有基础上补齐了离线安全原语（SSRF 形状校验、有界读取、日志脱敏）与对象存储/扫描/签名的**适配器骨架 + 本地实现**；
- **真实基础设施门禁全部未关闭**（见第八章），尚未部署、没有生产数据，不能称为生产可用。

最需要明确的一点是：

- 清小搭兼容的智能体 API 已实现，并通过本地合同测试；
- GLM/DeepSeek 的外部模型调用适配器已经编写；
- 但当前环境没有配置模型密钥，真实外部模型没有完成联网调用验证；
- 当前主访谈和推荐链路使用服务端状态机、结构化画像、确定性词法/概念召回与多目标排序，不是由大模型直接生成推荐；
- 简历和匹配报告使用确定性模板生成，不调用大模型补写经历。

因此，当前状态应表述为：**智能体接口和可信业务内核已经实现，但真实大模型尚未在当前环境的主链路中接通和验证。**

## 二、相对初版 radar 的主要更改

### 1. 从演示架构升级为双入口共享业务内核

初版已经有 Vue 3、FastAPI、三栏工作台、导师卡片、雷达图、散点图、个人信息页和信息平台页，但大量数据来自 JSON、前端 Mock、内存变量或占位接口。

当前版本保留了初版的主要视觉结构，同时改成两种入口共享同一套领域服务：

- 清小搭入口：通过 OpenAI-compatible `/v1` API 完成对话、画像确认和匹配结果解释；
- Web 入口：负责访谈、画像编辑、推荐比较、图表、招募信息、简历和行动记录；
- 两个入口共用访谈、画像、匹配、证据和身份授权逻辑，不在协议层复制排序代码。

### 2. 增加持久化访谈

初版更接近固定问卷或根据当前一句话立即推荐。当前版本新增：

- 内存态访谈会话（`QUESTIONNAIRE_SESSIONS`，v2.1 规划为服务端持久化，当前在内存）；
- 每轮只询问一个高信息量问题；
- 六类学生需求画像；
- 自然语言硬约束草稿；
- 地点、时间、学历阶段、语言、保密和毕业安排等约束的逐项中文确认；
- 可编辑的结构化画像；
- 用户显式确认后才允许进入匹配。

> 现状说明：访谈会话当前存在内存字典，进程重启即丢失；画像版本冲突检查在 v2.1 文档中规划但尚未在主链路中实现。

### 3. 导师匹配逻辑

初版的六维雷达重合度、热门度和行业性质主要用于演示，其中不少导师特质和评分缺少来源。当前匹配顺序：

1. 结构化硬约束过滤；
2. 可插拔召回；
3. 可配置多目标排序；
4. 证据化解释；
5. 输出反证、不确定性和待核实问题。

当前默认召回是确定性的词法/概念回退，明确不把它包装成真正的语义 embedding。排序把适配程度、证据覆盖率、证据置信度、保守排序分分开，避免资料稀疏的导师因为「只在少数维度得分较高」而被错误奖励。

### 4. 字段级来源与隐私（规划态）

> 现状说明：v2.1 文档描述的字段级来源、审核状态、发布状态、授权同意范围、有效期、下架状态、证据置信度、面向客户端的引用脱敏，以及「81 条旧导师记录受限」等，在当前仓库的 `mentors.json` 与 ORM 模型中**尚未实现**为独立字段或状态机。当前导师数据仍是 JSON 加载，没有审核/发布状态机。此项列为未完成。

### 5. 官方 2027 博士目录本地数据集（规划态）

> 现状说明：v2.1 文档描述的 110 院系 / 361 专业 / 1743 方向 / 4064 导师标签等官方目录数据集，以及抓取脚本 `scripts/crawl_faculty.py`，在当前仓库中**脚本存在但数据快照未随仓库提交**。此项列为未完成。

### 6. 身份与对象授权

初版和 patch 曾依赖固定 `anonymous`、自报学号或原始 Token。当前版本：

- Web 使用 `X-Student-Token` 头（当前为占位实现，`get_current_student` 原样返回 token 或 `anonymous`，**未做 JWT 解析**）；
- 训练触发使用 `X-Admin-Token` 头（与固定值 `admin` 比对）；
- v2.2 的对象存储路由对每个对象做 `owner_subject` 归属校验；
- 原始 Token 不作为业务 ID，不进入数据库。

> 现状说明：真正的服务端高熵 opaque 会话主体、清小搭终端用户 claim 验证、可信 claim 绑定等，在当前代码中**尚未实现**；当前 `student_id` 等字段仍由请求体携带，未在所有路由强制从 token 派生。

### 7. 私有文档能力（v2.2 新增骨架）

v2.2 在 `backend/app/services/` 与 `backend/app/api/v1/storage.py` 新增：

- `LocalStorageBackend`（写本地对象目录、随机 object key、`BoundedReader` 强制上限）；
- `BuiltinScanner`（扩展名/MIME/magic/大小检查，**明确不是病毒扫描**）；
- HMAC-SHA256 一次性下载令牌（`signing.py`）；
- 路由 `POST /api/storage/upload`、`GET /api/storage/download`（`Cache-Control: no-store`）、`DELETE /api/storage/objects/{id}`；
- 失败关闭：扫描失败/不可用时 `scan_status` 保持 `pending/quarantined`，对象不可下载。

> 未完成：真实私有 S3、真实 ClamAV、PDF/DOCX 内容解析、确定性生成真实简历与匹配报告的文档产物（当前简历生成仍是文本模板），均属未关闭门禁或未实现。

### 8. 离线安全原语（v2.2 新增）

- `services/security.py::validate_public_url`：URL 形状校验（必须 HTTPS、拒绝环回/私网/链路本地/保留测试域），是「公网 DNS/TLS/SSRF 复核」的离线近似；
- `services/security.py::BoundedReader`：有界流式读取，超限即抛错；
- `services/security.py::redact_token`：剥离 `Bearer`/`X-*-Token`/`token=`/`signature=`/Basic 口令；
- `tsinghua.py::scrape_faculty` 接入 URL 校验，拒绝 SSRF 形状目标；
- `deps.py::get_current_student` 日志改用 `redact_token`。

## 三、相对 patch 改版的主要更改

patch 提供了一些正确方向，包括 SSE 改用 `choices[0].delta`、增加 `[DONE]`、请求体改为 `messages`、后端导师分页、训练密钥移到 Header 等。当前版本保留并完成了这些方向，但没有直接采用 patch 的整套实现。

### 保留并完善

- OpenAI 风格的消息结构；流式 SSE；`[DONE]` 结束帧；Header 鉴权方向；后端限制返回数据量；前端真实解析流式响应；前后端错误状态处理。

### 重新实现或修复

- 同时支持 `stream=true` 和 `stream=false`；增加标准 `usage`；`/v1/models` 和 `/v1/chat/completions` 均要求 Bearer 鉴权方向；严格布尔值和合法 `finish_reason`；多模态消息支持结构化文本和 URL 内容；SSRF/形状保护（v2.2）；修复 `train_trigger` 测试与 Header 鉴权一致；补齐协议、身份、并发、隐私、文件和端到端回归测试。

## 四、当前人工智能与 API 的真实状态

### 1. 清小搭智能体 API（已实现，本地合同测试通过）

- `GET /api/v1/models`；
- `POST /api/v1/chat/completions`；
- 非流式响应；流式 SSE（`/api/v1/llm/chat`）；Bearer/Header 鉴权方向；多模态 URL 输入；访谈、画像确认、匹配和证据解释；本地协议合同测试。

未完成（见门禁）：没有公网部署；没有真实 `QXD_API_KEY` 和终端用户签名密钥；没有在清小搭真实生产入口完成端到端探测；附件能力受 `PUBLIC_BASE_URL` 门禁，未配置时返回「不可交付」。

### 2. 外部大模型 API（适配器已写，主链未接通）

代码中已经编写 GLM 和 DeepSeek 的真实 HTTP 调用适配器，GLM 失败时可降级到 DeepSeek；embedding 接口也可以在有 GLM 密钥时调用真实向量服务。但当前工作区和进程环境均未配置 `GLM_API_KEY`/`DEEPSEEK_API_KEY`/`QXD_API_KEY`/`QXD_END_USER_SIGNING_SECRET`/`PUBLIC_BASE_URL`。

同时，`llm_complete()` 当前**没有被主业务路由调用**（仅 `/api/resume/generate` 在有目标导师时尝试调用）。Web 访谈和清小搭对话实际调用的是访谈状态机与共享匹配服务。A4 默认匹配也不调用 embedding，而使用确定性词法/概念召回。

因此：

- 「外部模型适配代码已经写好」——是；
- 「当前系统已经真实调用 GLM/DeepSeek」——否；
- 「清小搭协议接口已经在本地实现」——是；
- 「已经与公网清小搭完成真实互操作」——否；
- 「当前推荐由大模型或深度学习模型生成」——否。

- 没有验证真实运营环境下的过期清理、审核时效和大数据量分页。

当前信息平台评价：**站内投稿和行动记录的基础闭环可用，但内容审核、正式发布、数据库持久化和外部投递尚未完成。**

## 八、10 项未关闭门禁（需真实基础设施与用户单独授权）

> 下列门禁均需真实基础设施、真实凭证或公网部署，而当前文档明确禁止这些操作（不部署、不申请密钥、不连接真实第三方、不重写 Git 历史）。v2.2 只完成了其中「离线可做」的部分；门禁本身**全部未关闭**。

### 1. 真实生产公网清小搭协议探测（未关闭）
- 未使用清小搭真实生产环境、正式凭证和公网地址。
- 需验证真实鉴权、终端用户签名、七轮对话、SSE 帧顺序、错误响应、超时重试及附件协议。
- 清小搭必须能从真实 HTTPS 地址取得附件；无公网基址时必须继续返回「不可交付」，不能降级成测试域（v2.2 已在 `resume.py` 落地此约束）。
- 需用户授权：真实凭证、外部网络请求、公网部署和平台联调。

### 2. 发布内容与 Git 历史审计（未关闭）
- 旧导师原始字段仍可能存在于 Git 历史、比较归档或旧版本文件中。
- 发布前要扫描当前文件、全部提交历史、归档、构建产物中的隐私数据、未授权导师信息、密钥和不应公开的数据集。
- 历史重写、归档删除和数据清理属于不可逆或高破坏操作，当前未授权。

### 3. 真实 PostgreSQL 双连接竞争验证（未关闭）
- 目前通过的是 SQLite 测试；**代码中没有任何 `FOR UPDATE`/行锁**，迁移为可移植 DDL。
- 还需在真实 PostgreSQL 上用独立连接复现投递与删除、重复投递、授权与删除等交错顺序。
- SQL 能生成不代表真实数据库竞争一定正确。

### 4. DOCX 的 Office/LibreOffice 逐页视觉验收（未关闭）
- 当前**未实现** DOCX 报告/简历文档产物（简历生成仅产出文本）。
- 即使产出，也需要在真实 Office 或可用的 LibreOffice 中逐页渲染验收。
- 在完成前只能声称「未实现」，不能声称 DOCX 视觉效果已验证。

### 5. 对象读取硬上限或流式实现（v2.2 离线实现，门禁未关闭）
- v2.2 已新增 `BoundedReader` 与 `MAX_UPLOAD/DOWNLOAD_BYTES` 硬上限，上传/下载路由强制有界读取；
- 但还需补充大对象、伪造大小、内存压力、并发下载和中途失败测试，以防内存耗尽型 DoS；
- 与真实对象存储（S3）一致性仍需在真实云上验证。

### 6. 真实 ClamAV 可用性及失败关闭探测（未关闭）
- v2.2 的 `BuiltinScanner` 仅做扩展名/MIME/magic/大小检查，**明确不是病毒扫描**；`ClamAVScanner` 为占位，未授权时按失败关闭返回不可用。
- 需要在真实 ClamAV 服务上验证干净文件、标准测试病毒样本、扫描超时、服务断开、异常响应和恢复过程。
- 需授权连接真实扫描服务；测试样本只能在受控隔离环境使用。

### 7. 真实私有 S3 读写、权限与加密探测（未关闭）
- v2.2 只验证了 `LocalStorageBackend` 与可插拔适配器；`S3StorageBackend` 为占位，调用即抛错。
- 需验证私有桶策略、最小权限凭证、TLS、服务端加密、随机对象键、禁止 public ACL、上传/读取/删除和失败重试。
- 需用户授权真实云账号、凭证、可能产生的费用和外部数据传输。

### 8. 公网 DNS、TLS、可达性及部署侧 SSRF 复核（未关闭）
- v2.2 的 `validate_public_url` 只做 URL 形状与 IP 字面量检查（离线近似）；
- 需真实验证 DNS 解析、证书链、域名匹配、有效期、重定向和公网可达性；
- 还需防御 DNS 重绑定、私网/环回/链路本地解析、异常端口、危险重定向及部署环境代理绕过；
- 需正式域名和部署环境后才能完成。

### 9. 反向代理/CDN 的签名令牌日志脱敏（未关闭）
- v2.2 的 `redact_token` 只覆盖应用日志；应用无法控制 Nginx、网关、负载均衡器和 CDN 的访问日志。
- 生产链路必须确保一次性下载令牌、签名和敏感查询参数不会写入任何上游日志。
- 需检查真实日志格式、缓存键、错误页、追踪系统、Referer，以及日志转发后的副本。

### 10. 生产日志平台、保留策略、告警与访问控制（未关闭）
- 当前只有本地结构化日志和进程内存储，不是完整生产监控系统。
- 上线前需要确定日志/指标存储平台、最小权限、传输和静态加密、数据保留与删除周期。
- 必须建立扫描失败、对象存储失败、异常授权、重复下载、5xx、延迟和容量告警。
- 还要验证日志不含用户画像、文件正文、原文件名、Cookie、凭证或签名令牌。

### 当前仍未授权的操作

即使逐项关闭上述技术门禁，也不会自动获得上线授权。目前仍不得：

- 部署或上线生产服务、绑定公网域名或创建公开 URL；
