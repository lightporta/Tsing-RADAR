# Tsing-RADAR v4.0.0 缺陷修复清单

> 记录本版本修复的**真实产品缺陷**（四段式：现象 / 根因 / 修复 / 验证）与
> **仍存在的环境性失败项**（如实记录，不掩盖）。
> 配套：`docs/偏差修正记录表_v4.md`（任务书 → 实现的等价物替换）、
> `docs/评估与提示词优化记录_v4.md`（离线评估闭环）。

## 一、已修复的真实产品缺陷

### BUG-1 导师信息咨询被吸收进画像（用户痛点直击）

- **现象**：访谈中回复「李琦老师的邮箱是什么」「听说李琦老师对学生很苛刻，有虐待学生的传闻吗」等，
  系统没有回答，反而继续问下一道画像题；「李琦老师最近在研究什么」被当作研究兴趣标签写进画像。
- **根因**：`dialogue_intent` 的咨询词表只有「怎么样/如何/评价」等评价类词，邮箱/电话/主页/缺点/
  传闻/研究内容等信息索取类词全部未覆盖；同时「老师」命中选择题锚词（`_CHOICE_EXTRA_ANCHORS`），
  消息被当作合法访谈答案放行进画像信号提取。
- **修复**：
  - `_MENTOR_QUERY_CONSULT` 扩展：邮箱 / 电话 / 联系方式 / 微信 / 手机号 / 主页 / 个人主页 /
    名额 / 缺点 / 传闻 / 八卦 / 研究什么 / 在做什么 / 做什么；
  - `_MENTOR_QUERY_PREFIXES` 新增「把 / 说说 / 听说」；
  - 命中后路由到综述级知识库块（`MENTOR_KNOWLEDGE` 意图 → `tools_registry.query_mentor_knowledge`），
    带「公开存档匿名主观评价聚合，仅作参考」声明；知识库未收录的字段诚实缺省，绝不编造联系方式/名额。
- **验证**：EVAL-048~053 mentor_knowledge 组 6/6；`test_mentor_knowledge.py` 正负例扩充
  （5 新增正例 + 4 新增负例）。

### BUG-2 他人事务被当作"我的研究兴趣"吸收

- **现象**：「把张三同学的联系方式给我」「把李琦老师的个人主页发给我」→ 回复变成访谈下一题，
  用户请求被静默吞掉。
- **根因**：越界守卫只做词表否定判定，没有"具体他人 + 索取信息"模式识别；姓氏后的名因
  `[\u4e00-\u9fa5]{1,4}` 贪婪匹配把「把张三」整体当姓名，百家姓门控落在「把」上失败。
- **修复**：`off_topic._is_other_person_request`——姓氏锚定正则
  `[百家姓][\u4e00-\u9fa5]{0,3}?(老师|教授|导师|同学)`（姓氏必须在匹配开头）+ 信息索取词
  （邮箱/电话/联系方式/主页/招生/名额/传闻/八卦/缺点/风评/口碑/改成/改为/修改成），
  跳过「我们/你们/大家/我/你/他/她」代词；在方向词判定**之前**执行（夹带"大模型"等方向词也不放行）。
- **验证**：EVAL-018~027 offtopic 组 10/10；`test_off_topic.py::TestOtherPersonAndFabricationGuards` 6 例；
  误伤回归：「希望老师手把手带我」「把我的研究兴趣改成机器学习」仍放行。

### BUG-3 编造请求未显式拒绝

- **现象**：「你帮我编一个导师推荐名单，不用真实数据」「编一份不用真实数据的导师报告」→ 被当作
  合法访谈答案或静默重跑匹配。
- **根因**：编造信号词无拦截路径。
- **修复**：`_FABRICATION_WORDS`（编一个/编一份/编造/瞎编/不用真实/造假/伪造/虚构）在
  `detect_off_topic_interests` 中先行拦截 → 温和重问（红线：绝不产出编造数据）。
- **验证**：EVAL-014（改写命令不谎称已改）通过；fabrication 单测 2 例。

### BUG-4 篡改指令被静默执行

- **现象**：「把李琦老师的 tolerance 从 94 改成 95 重新算一遍」→ 消息被「老师」锚词释放，
  进入正常流程。
- **根因**：对具体某人数据的篡改指令（改成/改为/修改成）无识别。
- **修复**：`改成/改为/修改成` 纳入 `_OTHER_PERSON_INFO_WORDS`（需同时命中具体他人，避免误伤
  「把我的研究兴趣改成机器学习」这类本人自述）。
- **验证**：EVAL-014 通过；tamper 单测 1 例；误伤回归单测 1 例。

### BUG-5 匹配态空数据复读（诚实空态刷屏）

- **现象**：确认画像后无匹配数据（`no_match` / `no_published_data`），此后每条消息都复读同一段
  「暂无数据」。
- **根因**：匹配态兜底只对 `matched + outcome.items` 生效，空结果状态（`no_match` /
  `no_published_data`）走不到能力引导分支。
- **修复**：`_POST_CONFIRM_OUTCOME_STATUSES = (matched, no_match, no_published_data)` 覆盖全部
  后确认状态；跑题消息 → 能力引导（不重复空态）；致谢/确认类 → 「不客气～有需要可以随时继续追问」。
- **验证**：EVAL-036（确认后再次确认 → 诚实空态）、EVAL-039~043 matched 组通过。

### BUG-6 离线评估多轮会话失效（工程缺陷）

- **现象**：评估脚本多轮用例 28/60 失败——每次回复都停留在 Q1/Q2，状态不推进。
- **根因**：`sync_user_transcript` 按 `user_messages[persisted_user_turns:]` 重放，评估脚本只发送
  最新一条消息导致增量丢失；且用 HTTP probe 预热身份会持久化「你好」轮次污染多轮会话。
- **修复**：评估脚本改为**每次请求携带完整累积历史**（与网关协议/黑盒测试同一口径）；
  身份预热改为直连 DB 创建 `ExternalIdentity` 映射（与 `resolve_qxd_principal` 同一 fingerprint
  逻辑），不再 HTTP probe。
- **验证**：60/60 用例通过（红线上涨到 17 例后仍 0 违规）。

### BUG-7 迁移链断言陈旧（测试缺陷）

- **现象**：`test_a6_migration_reaches_head_with_private_delivery_and_delete_tables` 断言
  `alembic_version == "0012"`，随迁移链合法推进（0013 dialogue_sessions / 0014 user_memories）
  持续失败。
- **根因**：硬编码旧版本号，未随迁移链更新（v3.1.7 起即为失败基线项之一）。
- **修复**：断言更新为当前唯一头 `"0014"`，附注释说明推进原因。
- **验证**：该用例单独运行 1 passed；全量失败集由 5 项降为 4 项。

## 二、仍失败的环境性基线项（如实记录，不掩盖）

以下 4 failed + 2 errors 与 v3.1.x 基线逐项一致，均为 **Windows 开发机环境性**，
不是 v4.0.0 引入的回归；在 Linux 生产/CI 环境下预期通过。已同步写入 README「已知问题」。

| 用例 | 现象 | 根因（Windows 环境性） |
| :--- | :--- | :--- |
| `test_a6_artifacts.py::test_linux_auto_font_prefers_reportlab_compatible_wqy` | 503 文档生成缺少可嵌入中文字体 | 用例按 Linux 路径配置 WQY 字体（`/usr/share/fonts/...wqy`），Windows 无该字体路径；生产 Linux 镜像自带字体即通过 |
| `test_l3_handoff.py::test_source_archive_is_byte_deterministic` | `application_image_missing` | 需要本地 docker daemon 已构建应用镜像；本机 docker daemon 未运行/无镜像（L3 交接验收口径） |
| `test_llm_configuration.py::test_missing_and_symlinked_llm_secret_files_fail_closed`（error） | `WinError 1314 客户端没有所需的特权` | 创建符号链接需要管理员/开发者模式特权，Windows 普通 shell 无该特权 |
| `test_llm_configuration.py::test_invalid_llm_secret_file_content_fails_closed[...]`（2 errors） | 同上 | 同一 symlink 前置失败导致的 parametrized error |
| `test_llm_configuration.py::test_llm_secret_permissions_reject_group_or_other_access` | `assert True is False` | Windows 文件系统不强制 POSIX 组/其他权限位，权限位读取语义与 Linux 不同 |

> 已在可修复范围内消除 1 项基线失败（BUG-7 迁移链断言），余下均为
> 不可在本机修复的环境项；修复原则：**不因本机环境差异放宽测试断言**。
