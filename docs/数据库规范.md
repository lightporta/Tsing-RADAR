# Tsing-RADAR 数据库规范

> 适用版本：v2.2.x
> 数据库：**统一 MySQL 8.x**（本地开发与生产同方言，不再支持 SQLite 运行时）
> 字符集：`utf8mb4` / `utf8mb4_unicode_ci`（支持中文与 emoji）

---

## 一、整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        应用层（FastAPI）                          │
└──────────────────────────────┬──────────────────────────────────┘
                               │ SQLAlchemy ORM
┌──────────────────────────────▼──────────────────────────────────┐
│                          MySQL 8.x                               │
│  ┌─────────────────────┐  ┌─────────────────────────────────┐   │
│  │   公开层（A/B/C 级）  │  │       私域层（D 级，物理隔离）    │   │
│  │  entities            │  │  private_feedback_raw           │   │
│  │  entity_names        │  │  private_signals                │   │
│  │  relations           │  └─────────────────────────────────┘   │
│  │  directions          │                                         │
│  │  entity_directions   │  ┌─────────────────────────────────┐   │
│  │  catalog_links       │  │       业务表（10 张）             │   │
│  │  opportunities       │  │  students / advisors / ...      │   │
│  │  claims              │  └─────────────────────────────────┘   │
│  │  sources             │                                         │
│  │  + advisors_public_  │                                         │
│  │    view (VIEW)       │                                         │
│  └─────────────────────┘                                         │
└──────────────────────────────────────────────────────────────────┘
```

### 设计原则

1. **三层分离**：公开事实层（A/B/C 级）/ 私域信号层（D 级）/ 业务表，物理分表，无外键泄露私域
2. **可追溯**：每条公开事实通过 `claims` 引用一条 `sources`，附两个 SHA-256（page / fragment）
3. **发布门禁**：所有新数据默认 `publication_status=withheld`，需审核才置 `published`；视图与公开接口只读 `published`
4. **隐私保护**：私域字段（consent_id / 评价原文 / 反馈者身份）永不进入公开接口
5. **推断有边界**：派生字段（radar_traits / popularity / score）不在事实接口暴露
6. **跨方言兼容**：迁移文件全部 ORM 优先，UUID 用 `String(36)`，时间戳用 `DateTime(timezone=True)`

## 二、表清单（24 张 + 1 视图）

### 2.1 公开事实层（A/B/C 级来源，RADAR 规范，9 张表）

| 表 | 用途 | 来源等级 |
| :--- | :--- | :---: |
| `entities` | 实体主表（person / organization / lab / advisor_group） | A/B |
| `entity_names` | 名称别名（official_zh / pinyin / historical） | A |
| `relations` | 实体关系（affiliated_with / leads / joint_appointment_with） | A |
| `directions` | 研究方向字典（level_1 → level_2 → specific_topic） | 派生 |
| `entity_directions` | 实体-方向关系（含 direction_scope 证据强度） | A/B |
| `catalog_links` | 招生目录事实（只表述「出现在目录」，不推断招生） | A |
| `opportunities` | 招聘/招生机会（带 valid_until 时效） | A |
| `claims` | **字段级证据声明**（每条事实一条 claim） | A/B |
| `sources` | 来源元数据（source_class A/B/C/D/E） | A/B/C |

### 2.2 私域信号层（D 级来源，物理隔离，2 张表）

| 表 | 用途 | 永不外泄字段 |
| :--- | :--- | :--- |
| `private_feedback_raw` | 学生反馈原文（D 级，永不公开） | `consent_id` / `source_ref` / `comment_text` |
| `private_signals` | 反馈聚合信号（≥3 份样本才形成） | 无原文，只存统计指标 |

**私域隔离规则**：
- `private_*` 表无任何反向关联到公开接口的字段
- 仅通过 `entity_id` 外键关联到公开层（单向）
- `consent_id` 仅用于合规审计，绝不进入任何对外响应
- 聚合规则：`sample_count < 3` 不形成公开结论；`3-5` 标注「样本较少」

### 2.3 治理层（发布门禁工作流，3 张表）

对应规范第 3.3 节要求的 `11_REVIEWS` / `12_ISSUES` / `13_BATCH_METRICS`。

| 表 | 用途 | 关键字段 |
| :--- | :--- | :--- |
| `reviews` | 审核记录（4 阶段审核链） | `review_stage`（collector_self_check / peer_review / publication_approval / independent_audit） |
| `issues` | 待核验问题（含 blocking 严重度门禁） | `issue_type`（identity_ambiguous / privacy_risk / ...），`severity`（blocking 必须解决才能发布） |
| `batch_metrics` | 批次质量指标（验收门槛物化） | `metric_name`（entity_count / private_data_leak_count / ...），`metric_status`（pass/fail） |

**审核工作流**（与第六节发布门禁配合）：
```
采集 → collector_self_check → peer_review（非采集者）→ publication_approval → independent_audit
                                                                                      ↓
                                                                              通过则 publication_status=published
```

### 2.4 业务表（10 张）

`students` / `advisors`（旧表，前端兼容）/ `match_records` / `resumes` / `recruitments` / `applications` / `feedback`（旧） / `questionnaire_sessions` / `training_samples` / `storage_objects`

### 2.5 视图

`advisors_public_view` —— 只投影 `publication_status='published'` 的 `person` 实体，是发布门禁的物化体现。

## 三、来源可信度分级（规范第六节）

| 等级 | 允许来源 | 进公开层 | 进私域层 |
| :---: | :--- | :---: | :---: |
| **A** | 学校研招网、院系官网、导师官方主页、实验室官网、ORCID | ✅ | — |
| **B** | DOI、CrossRef、OpenAlex、政府公示、NSFC 项目公示 | ✅ | — |
| **C** | 媒体报道、新闻公示（项目活动信号，需更多核验） | ✅（需核验） | — |
| **D** | 学生反馈、评价网、群聊转发 | ❌ | ✅ |
| **E** | 模型推断、编辑判断 | ❌（只生成 issues） | — |

**禁止事项**：
- 不得从招生目录推断「当前一定招生」「有名额」「录取意愿」
- 不得采集私人手机号 / 微信号 / 私人邮箱 / 家庭住址
- 不得从论文数量/引用数推断导师水平
- 不得把 D 级数据写入公开层

## 四、字段级证据（Claims）规范

每条公开事实必须附一条 `claim`：

```python
{
    "claim_id": "UUIDv4",              # 随机 UUID，不用姓名/URL/哈希
    "subject_type": "entity",          # entity / relation / direction / catalog_link / opportunity
    "subject_id": "<对应对象 ID>",
    "field_name": "official_homepage", # 规范字段名
    "normalized_value": "https://...", # 规范化值
    "raw_text": "原文片段（≤500字）",  # 忠实摘录，不扩大解释
    "source_id": "<sources.source_id>",
    "captured_at": "2026-08-05T10:00:00+08:00",
    "page_content_sha256": "64位hex",  # 整页内容指纹
    "fragment_sha256": "64位hex",      # 片段指纹（必填）
    "capture_method": "crawler",       # crawler / manual
    "publication_status": "withheld",  # 默认 withheld
    "review_status": "pending_review"
}
```

**关键约束**：
- 所有 ID 必须为随机 UUIDv4，禁止用姓名/URL/消息编号/本地路径作 ID
- `raw_text` 直接支持 `normalized_value`，不得扩大解释
- 命中私域（手机/微信）则整段丢弃，宁缺毋滥

## 五、数据来源接入方法（多源爬取框架）

### 5.1 框架位置

`backend/scripts/crawl_live.py` —— 多源爬取框架，支持 8 种来源类型：

```python
SOURCE_SPECS = {
    "official_homepage": {"source_class": "A", ...},  # 导师官方主页
    "lab_page":          {"source_class": "A", ...},  # 实验室官网
    "orcid":             {"source_class": "A", ...},  # ORCID 公开履历
    "openalex":          {"source_class": "B", ...},  # OpenAlex 论文
    "crossref":          {"source_class": "B", ...},  # CrossRef DOI
    "nsfc":              {"source_class": "B", ...},  # NSFC 项目公示
    "news_media":        {"source_class": "C", ...},  # 媒体报道
    "student_review":    {"source_class": "D", ...},  # 学生评价（仅入库 private_*）
}
```

### 5.2 使用方式

```bash
# 样本验证（先用 10 人跑通 pipeline）
python -m scripts.crawl_live --limit 10 --departments 电子工程系

# 全量抓取（建议在另一台机器持续跑）
python -m scripts.crawl_live --source-types official_homepage,openalex

# 按可信度筛选：只跑 A+B 级
python -m scripts.crawl_live --source-types official_homepage,orcid,openalex,crossref,nsfc
```

### 5.3 重要设计

- **官方主页白名单**：`is_tsinghua_official()` 只接受 `tsinghua.edu.cn` 域，避免误爬第三方页面
- **Polite 延迟**：默认 `polite_delay=2s`，避免被反爬
- **私域检测**：`sanitize()` 命中手机号/微信号即整段丢弃
- **学生评价**：自动爬虫**不采集**，由独立、带授权的问卷流程写入 `private_feedback_raw`
- **结果默认 withheld**：所有抓取结果需经审核才发布

### 5.4 接入效果排序（按可信度）

```
A 级（导师主页 + ORCID）  →  直接进 claims（current_official scope）
B 级（OpenAlex + DOI）     →  进 claims（publication_signal_only scope）
C 级（媒体 + 新闻）        →  进 claims（需 verification_status='pending' 核验）
D 级（学生评价）           →  只进 private_signals（≥3 份样本才聚合）
```

## 六、发布门禁工作流

```
build_database.py / crawl_live.py    →  batch JSON（全部 withheld）
        ↓
init_data.py --import-batch          →  MySQL（全部 withheld）
        ↓
人工/Agent 审核                       →  review_status='approved'
        ↓
init_data.py --publish-batch <id>    →  批量改 published
        ↓
advisors_public_view / v2 接口        →  只读 published
```

**命令**：

```bash
# 导入批次（幂等，重复 ID 更新）
python -m scripts.init_data --import-batch /path/to/batch.json

# 发布批次（需 ADMIN_TOKEN）
python -m scripts.init_data --publish-batch <batch_id> --admin-token <token>

# 旧 mentors.json 兼容导入
python -m scripts.init_data --legacy
```

## 七、迁移文件规范

### 7.1 跨方言约束（必须遵守）

- ✅ 用 `sa.String(36)` 存 UUID（避免方言原生 UUID 差异）
- ✅ 用 `DateTime(timezone=True)` 存时间戳
- ✅ 用 `sa.func.now()` / `sa.false()` 等方言无关 server_default
- ✅ 视图用 ANSI SQL（`CREATE VIEW ... AS SELECT ...`）
- ❌ 禁止 MySQL 专属语法（`AUTO_INCREMENT`、`ENGINE=InnoDB`、`COMMENT '...'` 等）
- ❌ 禁止 `sa.text("0")` 这种字符串字面量（用 `sa.false()`）

### 7.2 当前迁移链

```
0001_initial              →  业务表 10 张
0002_storage_objects      →  storage_objects（v2.2 对象存储）
0003_advisor_radar_schema →  RADAR 9 张公开表 + advisors_public_view
0004_private_signals      →  私域层 2 张表
0005_governance           →  治理层 3 张表（reviews / issues / batch_metrics）
```

### 7.3 环境变量驱动

`alembic.ini` 中 `sqlalchemy.url` 留空，由 `env.py` 从环境变量 `DATABASE_URL` 注入：

```ini
[alembic]
script_location = alembic
prepend_sys_path = .
sqlalchemy.url =     # ← 实际值在 env.py 中从 DATABASE_URL 读取
```

→ 替换 `.env` 中的 `DATABASE_URL` 即可指向任意 MySQL 8 实例（本地/生产），迁移文件直接复用。

## 八、历史数据迁移（一次性）

旧 SQLite 数据可由 `scripts/import_sqlite_data.py` 迁移到当前 MySQL：

```bash
python -m scripts.import_sqlite_data --sqlite-path ./tsing_radar.db
python -m scripts.import_sqlite_data --sqlite-path ./tsing_radar.db --dry-run  # 只统计
```

**注意**：
- 脚本只做一次性迁移，**业务运行绝不走 SQLite 连接**
- 幂等：用 merge（基于主键），重复运行不重复插入
- 自动跳过 ORM 中已不存在的旧列

## 九、自检清单

部署/迁移后用以下 SQL 自检（参考 `scripts/build_database.py` 的同名约束）：

```sql
-- 1. 所有新记录默认 withheld（无 published 泄漏）
SELECT COUNT(*) FROM entities WHERE publication_status='published';  -- 审核前应为 0
SELECT COUNT(*) FROM claims WHERE publication_status='published';

-- 2. 所有 ID 为 UUIDv4 格式
SELECT COUNT(*) FROM entities
WHERE entity_id NOT REGEXP '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$';

-- 3. claims 必有 fragment_sha256
SELECT COUNT(*) FROM claims WHERE fragment_sha256 IS NULL OR fragment_sha256='';

-- 4. 外键完整性
SELECT COUNT(*) FROM claims
WHERE source_id IS NOT NULL
  AND source_id NOT IN (SELECT source_id FROM sources);

-- 5. 私域表无泄漏到公开层（应永远为 0）
SELECT COUNT(*) FROM information_schema.columns
WHERE table_name LIKE 'private_%' AND column_name IN ('consent_id', 'comment_text')
  AND table_name NOT LIKE 'private_%';  -- 不存在即合规

-- 6. 视图只读 published
SELECT COUNT(*) FROM advisors_public_view;  -- 等于 entities 中 published person 数
```
