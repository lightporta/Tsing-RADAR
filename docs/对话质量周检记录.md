# 对话质量周检记录（v4.3.0 起生效）

> 目的：以固定抽样口径周期性检视对话质量，把"感觉不对"转成可归因、
> 可处置、可回归的记录。每周一次（建议固定工作日），每次 ≤30 分钟。
> 本文件为模板 + 首版记录；后续每周新增一节，不修改历史记录。

## 一、抽样口径（固定，保证周间可比）

1. 从生产日志抽取上一自然周的 QXD 对话会话（`/v1/chat/completions`，
   session 级），**随机抽 20 个会话**；
2. 每会话取全部轮次（不截断），重点看：
   - 访谈期（含确认门之前）的闲聊/跑题/敏感处理；
   - 表达层重写生效轮（`chat_expression status=available` 日志）与降级轮
     （`disabled/unavailable/rejected_output`）；
   - 匹配态的工具调用（意图词路由 + 自主调用）、收藏、联系确认门；
3. 无生产环境时（当前阶段）：改跑 `python scripts/eval_offline.py`
   （75 例），以失败例与新增抽样手工对话替代。

## 二、常见失败模式分类（处置映射）

| 模式 | 表现 | 处置方向 | 回归验证 |
| :--- | :--- | :--- | :--- |
| 跑题误伤 | 合法访谈答案被当跑题重问 | 收紧 `off_topic` 词表/锚词（宁放过不误伤） | `test_off_topic.py` 新增正例 |
| 跑题漏放 | 无关话题被写入画像/闲聊超过 5 轮 | 扩词表 / 检查会话计数 KV | `test_off_topic.py` 新增负例 |
| 编造 | 出现知识库/招募之外的联系方式、名额、评分 | 检查拒答门与逐字校验是否被绕过 | eval redline 组扩例 |
| 语气生硬 | 客服腔 / AI 自称 / Markdown 泄漏 | 提示词版本迭代（**新增版本文件，不覆盖**）+ 闸门词表 | `test_chat_expression.py` / `test_prompts.py` |
| 承接重复 | 连续多轮同一开场（"好的，那我们…"） | 跨轮防重复阈值调优 / 提示词钩子强化 | `TestRepetitionGate` |
| 工具误调 | LLM 调了不该调的工具 / 幻觉参数 | 注册表白名单 / `_coerce_arguments` 收紧 | `test_autonomous_tools.py` 扩对抗例 |
| 确认门泄漏 | 未确认即执行联系/报告等敏感操作 | 检查二次确认门路径与失效语义 | `test_contact_request_full_gate` |
| 降级异常 | 无 key 环境出现非确定性文案 / 超时 | fail-closed 路径排查 | eval degradation 组 |

## 三、处置规则

1. 每条失败按上表归类；**不能归类的先记"未分类"**，攒 3 条以上再定类；
2. 处置三选一：改模板版本（prompt 纪律）/ 改词表 / 加闸门——
   涉及红线的（编造/确认门泄漏）**当周必须修**，其余可攒批；
3. 每次处置必须带回归用例（单测或 eval 扩例），先红后绿；
4. 结果记入下表，CHANGELOG 随下一版本汇总。

     补充的真实效果待有 key 环境复检（部署后首周重点）。
