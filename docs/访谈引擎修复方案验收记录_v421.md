## 六、v4.2.2 真实 GLM key 复验增补（2026-08-23）

> 本版本首次拿到**真实 GLM API key**，对 LLM 增强链路做了此前从未有过的端到端
> 真实验证，并因此发现、修复了一个隐藏缺陷（模板与校验器自相矛盾）。

### 6.1 发现：增强链路 100% 被拒（此前无 key 无法发现）

- 现象：真实 GLM-4-Flash 输出经 `_validate_expression` 全部返回 `status=unavailable`，
  增强从未生效，全部静默降级回固定模板。
- 根因：v3 模板自然度 C 指令「选项意译」（"选项融进句子里说"），而校验器要求
  「全部选项逐字 + 题干 ≥6 字片段」——模板与校验器自相矛盾；真实题库单选长标签
  （如"更爱追根究底：理论与原理"）GLM 无法逐字引用；题干 ≥6 字片段同样无法命中。
- 影响：v4.2.0 宣称的「多轮自然度增强」实际从未生效（降级输出仍正确，只是不自然），
  且每次被拒调用浪费 ≤4s（`LLM_INTERVIEW_ENHANCEMENT_TIMEOUT_SECONDS=4.0`，有界）。

### 6.2 调和（宁降级不出戏，红线不放松）

| 项 | v3（矛盾） | v4（调和后） |
|---|---|---|
| 模板 C | 选项意译 | 有选项时**逐字引用全部选项**（不改写/不省略）；无选项时保留题干 ≥5 字原句片段 |
| 校验器 | 全部选项逐字 + 题干 ≥6 字片段（双重锚点） | 选项题以**全部选项逐字**为唯一内容锚点（严格强于片段检查，防误伤）；自由文本题保留题干 ≥5 字片段（`_core_fragments` 6→5） |
| 版本管理 | v3 已登记 | `rewrite_template_v4.txt` 新增 + `prompt_versions.json` current=v4 + `_CURRENT_VERSIONS` 锁步（不一致即兜底 v1） |

- 红线不变：`test_render_rejects_missing_option_label`（漏任一选项即拒）、
  `test_render_rejects_missing_question_core`（自由文本题无题干核心即拒）等既有契约
  全部保持绿色；新增 `TestV422TemplateHarmonization` 5 例锁定调和后行为。

### 6.3 真实 key 复测结果（如实记录）

- 自由文本题（约束澄清式动态题，题干 ≥5 字片段）：GLM-4-Flash 输出
  「这个条件是必须的，地点得是"北京"，这是不能变的吧？确认这个条件吗？」——
  零 ≥5 字原句片段 → `status=unavailable` → 降级确定性模板。
- 单选长标签题（研究方式 4 选项）：`status=unavailable` → 降级。
- 结论：当前模型（GLM-4-Flash）对逐字引用指令倾向意译，事实保真红线下增强按设计
  降级；降级成本有界（仅兴趣→研究方式一轮 1 次调用 ≤4s，单选轮零调用）。模板与
  校验器矛盾已消除，后续模型（或 API 参数调整）可逐字引用时增强自动生效，无需改码。
- 端到端其他复验：问题5 非流式开关生效（stream=True → 200 + application/json）；
  P0-J/P1-D 六组确定性路由全部命中（见《v4.2.1线上回归报告》§六）；全量门禁
  **882 passed / 4 failed（同一环境性基线）/ 2 skipped / 2 errors —— 0 新增失败**。
